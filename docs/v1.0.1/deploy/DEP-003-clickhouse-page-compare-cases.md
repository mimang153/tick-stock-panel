## 一、环境与前置条件

### 1.1 两栈地址

| 栈 | 页面 | API | 存储 | 登录 | 代码版本 |
|---|---|---|---|---|---|
| **dev（待验证）** | `http://localhost:3011` | `http://localhost:3018` | ClickHouse（`tsp` 库） | **需要**（已设访问密码） | v0.3.37 |
| **origin（oracle）** | `http://localhost:4011` | `http://localhost:4018` | Parquet + DuckDB | 免登录（内网放行） | v0.3.37，代码快照无 git |

- 两栈前端代码完全相同（同一版本 v0.3.37），所以**布局、文案、控件位置应一致**；差异只应来自后端数据/口径。
- 两栈数据目录互相独立、各自同步，互不写入。

### 1.2 执行前准备

1. **浏览器**：Chrome/Edge 各开一个无痕窗口（或两栈各用一个 profile），避免 localStorage / cookie 串味。建议视口统一 `1600×900`、缩放 100%。
2. **dev 登录**：先打开 `http://localhost:3011`，用项目访问密码登录；确认顶部不再提示「未登录」。若 API 返回 401，页面会跳 `/login`。
3. **固定区间**：**必须显式指定同一交易日区间，绝不比对「最新交易日」**（两栈同步时点不同，最新日天然不同，见 §16.6）。
   - 本轮统一用 **`2026-11-12` ~ `2026-11-13`**（中间交易日，避开 11-16 最新日）。若某页面无法选日期，则以页面当前展示的**同一日期**为准，并在记录里写明实际日期。
   - 个股/指标类用例固定标的 `600519.SH`（贵州茅台，有除权历史）与 `000001.SZ`（平安银行）各看一遍。
4. **清缓存**：两栈都按 `Ctrl+F5` 强刷一次，避免旧 generation 缓存干扰。
5. **证据留存**：建议新建 `gui-test-diff/` 目录，截图命名 `TC编号_栈_页面.png`（如 `TC03_dev_kline.png`）。

### 1.3 已知允许差异（**不算缺陷，不要报**）

判差异前先对照此表，避免把预期差异当问题（依据：验收日志「双栈对照差异判定」）：

| 项 | 允许差异 | 原因 |
|---|---|---|
| `instruments.as_of` | 不同（CK=11-17 / Parquet=11-15） | instrument_sync 只写 CK，本地 parquet 是遗留镜像、非权威读源 |
| 证券简称中的 `XD` 前缀 | 约 7 处不同 | 除权除息前缀动态标注，数据源时点差 |
| 标的总数 | 5537 / 5892 等 | dev 从 CK 维表读、origin 从 DuckDB instruments 读，统计口径不同 |
| `/api/data/status` 的 `rows` | 两边都是 0 | 统计口径写死为「零数据扫描」，**不代表空库**；真实数据在页面/接口里 |
| 实时行情（盘中） | 不对照 | 两边轮询时点不同（§16.6） |
| 最新交易日 | 不对照 | 同步时点不同 |

### 1.4 差异判定规则（§16.4，强制）

发现任何差异按此顺序处理：

1. 先确认**两栈输入是否真一致**（同一日期、同一标的、同一筛选条件）；输入不同 → 不算缺陷。
2. 再查是否是上表「已知允许差异」；是 → 记录为预期，不算缺陷。
3. 再查 origin 是否有已知缺陷；是 → 不作为基准。
4. 以上都不成立 → 判为**新栈可疑缺陷（P1）**，截图 + 记录复现步骤，并交叉 API 数值确认。
5. **每一条差异（含预期差异）都要写进执行记录**，不允许只写「通过/失败」。

## 二、测试用例

### 用例分级

- **P0**：核心口径，必测，任一不过不得进入验收结论。
- **P1**：重要展示/交互，必测。
- **P2**：补充项，时间允许时测。

---

### TC-01 · 空态与整体可达性（P1）

> 对应 §8 第 1 项。注意：本轮两栈**都已有数据**，真正的「空库启动」无法在当前环境复现，本用例退化为「各页面可达、无白屏」。

**步骤**
1. 依次打开下列路由（dev 与 origin 各一遍），每个停留 3 秒：
   `/`、`/watchlist`、`/screener`、`/backtest`、`/data`、`/indices`、`/regime`、`/factors`、`/settings`。
2. 每个页面按 `F12` 打开控制台看 `Console`。

**对比点**
- 两栈页面结构、菜单、文案一致；无白屏、无「数据加载失败」提示。
- Console 无红色 error（忽略 favicon 404 等无害告警）。

**通过标准**：9 个路由在两栈均正常渲染，无 500、无 console error。

**记录**：任一页面异常，截图 + 记 URL 与 console 首条报错。

### TC-02 · 看盘主页（Dashboard）横截面（P0）

> 对应 §16.5「市场概览/板块/涨跌停计数」与 §8 第 5 项。路由 `/`。

**步骤**
1. dev 与 origin 同时打开 `/`，确认停在 `2026-11-12` 或 `11-13` 的横截面。
2. 逐项比对页面上的汇总数字：上涨/下跌家数、涨停/跌停家数、成交额、市场概览卡片、板块列表（名称与涨跌幅排序）。
3. 若页面有板块/概念切换 tab，逐个切一遍并比对排序前 10。

**对比点**
- 计数类数字**必须完全一致**（这是 projection 横截面路径，存储切换最易出问题处）。
- 板块列表**顺序 + 数值**一致；名称允许出现 1.3 节的 `XD` 差异。

**通过标准**：计数完全一致；板块排序与数值一致（预期差异除外）。

**证据**：`TC02_dev_dashboard.png` / `TC02_origin_dashboard.png`。

### TC-03 · K 线与复权口径（P0）

> 对应 §16.5「K线（含复权切换）」与 §8 第 2 项。路由：从 `/watchlist` 或 `/` 点击标的进入 `/analysis/:menuId`。

**步骤**
1. 两栈分别进入 `600519.SH` 的个股分析页，日期区间选 `2026-11-01` ~ `2026-11-13`。
2. 比对 K 线图形态：蜡烛图的高低点、涨跌颜色、成交量柱相对高度。
3. 鼠标悬停 `2026-11-12` 的 K 线，比对读数：open/high/low/close、涨跌幅、成交量、MA5。
4. 切换到 `000001.SZ` 重复 2~3。

**对比点**
- 数值读数**逐值一致**（浮点容差 1e-9）；K 线形态应肉眼一致。
- 注意：当前 API **没有 `adjust` 参数**，界面固定展示「日K（前复权）」（代码里就是前复权口径）。所以**只比对前复权口径**；若某端另有复权切换控件，再对比 `none`/`forward` 两态，否则在记录里注明「无切换控件，仅前复权」。

**通过标准**：悬停读数一致；图形态一致（无错位、无缺失蜡烛）。

**证据**：`TC03_dev_kline_600519.png` / `TC03_origin_kline_600519.png`。

### TC-04 · 技术指标切换（P0）

> 对应 §16.5「看盘主页指标（MA/EMA/MACD/BOLL/KDJ/ATR/RSI）」。在 TC-03 同一页面执行。

**步骤**
1. 两栈在 `600519.SH` 分析页，依次切换指标：MA、EMA、MACD、BOLL、KDJ、ATR、RSI。

**对比点**

**通过标准**：7 个指标形态与读数一致，无缺失线、无 NaN 显示。

### TC-05 · 选股器（P0）

> 对应 §16.5「选股器结果条数与列表」与 §8 第 4 项。路由 `/screener`。

**步骤**
1. 两栈打开 `/screener`，确认默认筛选条件一致。
2. **内置条件**：选一个内置策略（如「均线多头」类），执行筛选，比对结果**总条数**与列表前 20 的标的/数值。
3. **自定义 SQL**：在自定义条件框输入一条固定 SQL（两栈完全一致），执行，比对条数与前 20 行。
4. 记录筛选所用的条件/SQL 原文。

**对比点**
- 结果条数必须一致；列表顺序与标的集合一致；数值列一致（预期差异除外）。

**通过标准**：内置 + 自定义各一次，条数与列表一致。

**证据**：条件原文写入记录，截图 `TC05_*_screener.png`。

**对比点**

## 附录 A · 为什么只做手工、不自动化截图对比

探查结论（2026-11-17）：

- **可做半自动**：两栈服务在线、版本一致、都有真实数据；node/npm 可用。理论上可写 Playwright 脚本做「逐路由打开 + 抓页面 API 响应与 DOM 文本 + console 检查」，这部分能可靠自动化。
- **不做像素级截图判定**：图表用 ECharts + lightweight-charts（canvas 渲染），抗锯齿、DPR、动画帧会让数据相同的两栈也产生像素差异，假阳性高；「图表形状一致」本质仍需人眼判断。
- **两道门槛**：dev 栈已设访问密码（自动化需凭据，会话注入对已运行进程无效）；仓库无 playwright/chromium 与 e2e 设施，需从零安装。
- 因此本轮采用**手工用例文档**；后续若投入自动化，优先方向是「API 响应/DOM 文本结构化比对 + 截图仅作留证」，而非截图像素 diff。
- 数据层自动化对照已由 `backend/scripts/cmp_stacks.py` 完成（3 数据集零差异），本文是其页面层的补充。
